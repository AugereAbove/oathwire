# Pre-deployment audit — 2026-10-23

**Decision: suitable to proceed to owner-reviewed deployment planning, but not yet verified as a live service. Deployment remains on hold.** No AWS account API was used to create, modify or delete resources. Validation, SAM translation, builds, SDK integration, secret scanning and pricing research were performed locally. Public price lists were fetched anonymously.

Expected monthly list-price model: **$0.71 idle**, **$2.41 for the defined small beta**, **$7.57 with sustained destination timeouts**. Plan for approximately $0.60–$1.50, $2–$5 and $8–$15 respectively, before taxes and free allowances. These ranges do not cover arbitrary traffic or guarantee a bill ceiling. The beta is 20 MAUs, 10,000 ~1-KiB events/month, two destinations and 10% one-extra-attempt retries. See [cost assumptions, rates and risks](costs.md) and [machine-readable calculations](cost-model.json).

## Findings and local corrections

1. **Change-set approval was insufficient:** the original manual workflow executed SAM deploy automatically once the job started. It is now plan-only with an explicit false-by-default planning authorization input; it cannot execute or publish. The future planning role must exclude execution permission.
2. **Broad SAM-managed role permissions:** generated managed policies granted logging/SQS actions across the account. Replaced with explicit inline roles scoped to Oathwire tables, necessary indexes, its queue and own log streams. The worker cannot write signing secrets; the API needs secret Get/Put for rotation.
3. **No DynamoDB throughput ceiling:** added per-table/index maximum on-demand units. These improve burst control while preserving durable recovery; throttling can cause 503s or later retries.
4. **Implicit Cognito pricing tier:** pinned Lite/classic instead of relying on the Essentials default.
5. **Potential KMS charges:** `SSEEnabled: true` selected a billable AWS-managed KMS key. Changed both tables to AWS-owned encrypted storage; at-rest encryption remains enabled.
6. **Log group creation race:** fixed log group names and explicit Lambda LoggingConfig dependencies ensure retention is applied before invocation.
7. **Unalarmed internal failures:** partial batch and item reconciliation errors did not increment Lambda's invocation error metric. Added a scoped metric filter/alarm.
8. **Recovery runtime pressure:** 500 sequential records could exceed the 20-second Lambda timeout. Added a 12-second soft admission budget and recovery test; per-call SDK stalls remain recoverable through leases/due records.
9. **Network/input edge cases:** reject IPv6 outside allocated global-unicast `2000::/3` in addition to special ranges, and reject compressed JSON instead of spending CPU inflating unauthenticated requests.
10. **Revoked-key storage growth:** revoked hash records now expire after seven days; active keys remain valid until revoked.
11. **Unsupported development tooling:** upgraded deprecated ESLint 9 to supported ESLint 10 after confirming TypeScript-ESLint peer compatibility.
12. **Secret scan false positives:** Gitleaks flagged the literal `Authorization: Bearer YOUR_API_KEY` example and the public AWS HTTP API price SKU `T5HBB5E3DWVQPUNF`. Both were checked against their source and narrowly excepted by exact match. No real credential was found; no broad directory exemption was used for Git history.

## Remaining steps before live use

1. Owner reviews this audit and costs. No authorization is inferred from profile setup or this report.
2. Configure a non-root, short-lived [AWS CLI profile](aws-profile.md), confirm account/region, billing visibility and required service/concurrency quotas. AWS CLI v2 is not installed/configured in this workspace yet; SAM is available through `uvx`.
3. Review account-specific least-privilege planning and CloudFormation roles, artifact bucket, GitHub OIDC trust and environment reviewers. These are prerequisites, not existing configured resources.
4. **Only after separate authorization**, create/upload the deployment artifacts and unexecuted change set. Inspect its exact ARN, resources, parameters, IAM changes and replacements. Obtain execution approval for that exact plan.
5. Execute the approved plan; then review and authorize a second change set that replaces the temporary localhost callback with the actual CloudFront origin. Build/publish frontend assets only after publication authorization.
6. Invite two test users, confirm SNS/budget emails, and run every live scenario in [deployment.md](deployment.md): success, temporary 503/recovery, exhaustion, replay, revoked key and cross-tenant denial. Record actual evidence before calling the MVP complete.
7. Run a load test only after the service works and a request/spending budget has been approved. Refine the model using actual consumed units/durations; no performance measurements are claimed now.

Known deliberate limits: no exactly-once delivery or event ordering, seven-day history, sampled statistics, page-local event filters, five lifetime destination configurations per project, no automatic user-session refresh, no PITR/backup recovery from operator deletion, and no hard account-wide spend cap. Account-specific deployment permissions and live tests remain outstanding; unrelated local implementation/testing has continued throughout the hold.
